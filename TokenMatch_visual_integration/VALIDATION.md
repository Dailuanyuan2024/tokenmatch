# 本地验证记录

验证环境：Python 3.12.14、PyTorch 2.3.1+cpu、NumPy 1.26.4、OpenCV 4.10.0、h5py 3.11.0、einops 0.6.1；DataLoader workers=0。

模型来自本次上传的当前项目，主干 SHA256：
`54467c755baa0584bea33dbe449fd102a6d3c4ba293c01d6afbb32b2bae27a1b`。

输入为本地生成的纹理图像、相机标定及可见性列表，使用真正的 OpenCV SIFT、最近邻匹配和完整 TokenMatch 主干。**没有使用服务器上的真实 YFCC100M 图像，也没有加载服务器的旧检查点；以下不是论文性能实验。**

| 检查 | 结果 |
|---|---|
| 所有 13 个 Python 模块语法检查 | 通过 |
| 归档按 train/val 解压、重复解压复用、排除测试场景、拒绝路径穿越 | 通过 |
| 仅含测试场景的归档 | 按预期停止，`real_training_started=false`，生成可返回的日志 ZIP |
| OANet 主点偏移还原、相对位姿及标签计算 | 通过；极线标签与原 `loss.batch_episym` 一致 |
| 262 维视觉特征与对应点同步采样 | 通过 |
| 相同随机种子下两版的原主干初始权重 | 完全相同 |
| 视觉嵌入为零时两个 stage 的 logits | 与原主干逐元素相同 |
| 完整主干分类损失反向传播 | 通过，视觉分支梯度非零且有限 |
| global step=20000 启用几何损失后的反向传播 | 通过，参数梯度有限 |
| 20 步视觉版训练及检查点保存 | 通过，loss 从 1.5893748 到 1.0217526；第 20 步视觉梯度范数 0.6676036 |
| 从第 20 步恢复到第 21 步 | 通过，恢复优化器/调度器/RNG；loss=0.9907455 |
| 坐标版 batch size=2 的训练与验证 | 通过，2 步 loss 从 1.4640627 到 1.4144017 |
| 4000 SIFT 点、最长边 1600 的评估 CLI | 坐标版、视觉版均通过，无输入失败 |
| 验证集阈值搜索及阈值文件绑定检查点 | 通过；流式实现每对图像只前向一次 |
| 复用现有项目位姿与 AUC 函数、失败计入分母 | 通过 |
| 推理输入 | 只有 `xs` 和 `visual`，不传训练标签或真实位姿 |
| 正式评估入口拒绝 20 步检查权重 | 通过 |
| 状态与日志打包 | 通过，不含权重或图像 |

这些小规模输入的位姿 AUC 没有科研比较意义，不能作为表 8 的结果。20 步优化只验证数据、梯度和优化器的连接；原训练默认在第 20000 步才启用几何损失，因此另做了几何损失反向检查。

尚未在本地验证：CUDA 执行、A5000 显存占用、服务器数据是否齐全、500000 步正式训练、真实 YFCC100M 指标、两个 GPU 后台进程的实际运行。工作进程测试受本地环境禁止 UNIX socket 的限制，workers=1 模式未通过；服务器默认 4 workers 的行为需检查真实日志，也可指定 `--workers 0`。

旧实验原始视觉代码和精确阈值没有找回。当前包中的 MLP、归一化、相加融合和验证阈值搜索属于本次明确记录的重建设置，不能表述为旧实验细节已被证实。
